## Stack & Survive artwork

Board geometry, fallback resource shapes, traffic markers and status effects are generated by project code. The targeted building sprites below are original project-created files, not imported game-art packs. Later imported assets need their own source and license entries; do not assume a whole hosting site is CC0.

`apps/web/src/building-art.ts` provides platform, state overlays, Internet art and fallback resource geometry. `apps/web/src/environment-art.ts` creates indoor floor tiles, racks, cooling/utility equipment, conduit, lighting and safety markings (original project code, introduced in #81; no third-party files imported). Environment stays procedural following the #91 quality decision. Official badges remain separate DOM images, never baked into these shapes or the PNGs.

## Original production building sprite set (#91)

- Author/provider: Stack & Survive project, AI-assisted original vector construction authored during the owner-requested implementation.
- Created: 2026-09-12. No external pack was retrieved; no commercial/reference-game art or Azure SVG paths were copied.
- Source/creation recipe: `scripts/export-building-sprites.mjs`; generated editable vector sources: `art/buildings/*.svg`. Update the recipe when changing artwork, then regenerate, rather than silently losing manual SVG edits.
- Ownership/license status: original project work; no open-source/public redistribution license has been selected. Employer/Hackathon/IP review remains required before public release. Do not label these files CC0.
- Transformation: rasterized original 256-unit SVG at DPR 2 into transparent 512×512 PNG with Playwright Chromium. No icon content included. Metal/material shading is original SVG gradient art, not a captured game scene or opaque background.
- Export: from the repository root with installed dependencies and Chromium, run `node scripts/export-building-sprites.mjs`. `art/buildings/bounds.json` records measured alpha bounds, byte sizes and SHA-256 values. Browser rasterization may differ by Chromium version; review regenerated diffs and manifest intentionally.

Display sizing uses measured nontransparent bounds, not the padded source canvas. `building-assets.ts` computes origins, display dimensions and visible rectangles from `bounds.json`; the logical footprint remains 116×96 and existing editor placement rules are unchanged. Selection and badge/annotation placement use the resulting art envelope. App instances share one module asset rather than four separate building variants. Shadow/platform, image, modules, status/selection, VFX, captions and official badges remain independent layers.

Loading uses five local Phaser textures. Missing or corrupt body/module files degrade to procedural resource artwork and do not disable the simulation. These are authored production-file replacements integrated into the game, not proof of pixel-equivalence with the owner's rendered concept reference. Approximate texture storage: five 512×512 RGBA textures = 5 MiB before driver/mipmap overhead; one texture is reused for all App modules. Encoded PNG total: 196,584 bytes. Validate actual load, rendered bounds, performance and source manifest through tests when changing this set.

Verification at introduction: 45 QA browser cases passed with alpha bounds and served PNG SHA-256 checked against the manifest, actual Phaser origins/depth/module alpha checked, and missing/corrupt file fallback exercised. The sprite QA bundle was approximately 291.65 kB minified / 92.61 kB gzip, versus approximately 286.94 / 90.85 kB for the preceding procedural environment build; PNGs are additional static downloads. One measured peak run on Apple M1 Pro/ANGLE Metal, Chromium 153.0.8010.12 at 1440×900 DPR 1: 1,201 frames / 20.0063 seconds (60.03 FPS), p95 interval 16.8 ms, 62 representative markers and 20 simulation ticks. This does not establish performance on other devices or aesthetic equivalence to the reference.
