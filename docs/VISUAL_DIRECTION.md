# Stack & Survive — Visual Direction

Version: 0.4. Implemented foundation PR #140; Production Quality Epic #142 is future work. [Resource Visual States](RESOURCE_VISUAL_STATES.md) and [Simulation](SIMULATION_SPEC.md) own truthful states and outcomes.

> Official Azure icons identify the service. Custom game assets create the game world.

## World and facilities

An indoor data-center game, not a portal, floating diagram or unrelated sci-fi collage. Desktop: Internet → Edge → central App → Cache/read branch and dominant SQL. Narrow layouts may stagger the same graph. Frame the playable aisle with subordinate racks, cooling, PDUs, vents, trays and walls; no outdoor roads/trees/cars/pallets. Props never obscure packets, bays, pads or badges.

| Resource | Required visual grammar |
|---|---|
| App | One solid module per actual instance; empty next bay and later locked bays; one construction scaffold; no phantom servers |
| SQL | Dominant fixed data core; separate read/write pressure sides, no implied upgrade |
| Cache | Pad → construction → compact memory facility; hits terminate, misses/overflow continue, writes remain direct |
| Edge | Pad → gateway construction → active ingress; queued/scheduled boost differs from actual filtering |
| Internet | Offered-demand source and actual active limiter cue |

Reference images must cite attainable architecture/tick fixtures. App1 at 220 RPS overloads App, not SQL; do not paint unsupported drama. Active Cache and Add Cache pad cannot coexist. Runtime scale-in and SQL scaling are not current actions.

## Traffic, lights and motion

Cyan/blue Browse blocks, amber Order blocks and corrupted red Bot blocks differ by shape/detail, not only color. Lanes use dark bed/translucent activity/bright directional center. Cache hit, Edge filtering, intake limiting and downstream failure have distinct endpoint cues. Representative pressure is not a waiting count or promise of eventual completion.

Use reusable textures, bounded pooled effects, lightweight shadow/light-pool/emissive overlays. Avoid dynamic 3D lighting and uncontrolled overdraw. Orange warning/red critical require additional shape/text cues. Relief and filtering feedback only follow actual processing. Reduced motion retains static meaning; pause/terminal does not replay rewards.

## Pads, HUD, results and title

Expansion uses floor pads with minimal role/+ and discoverable real costs/durations through hover/focus/tap confirmation. App expansion belongs to physical bays. Hit targets remain accessible and unoccluded.

HUD: budget/demand/availability/primary pressure plus Learn/Pause. No persistent construction/sidebar telemetry or separate Insights/Events/Why buttons in normal play. Local cards are state/action first; education stays in one Learn surface.

Results retain the stopped world, highlight actual outcome/cause/score/NBV, offer grounded advice and focus primary replay. Decorative TitleWorld previews the theme without running a scenario; Start Game stays strongest. Keep visual materials and typography consistent across title/world/result.

## Production-quality policy

[Asset Strategy](ASSET_STRATEGY.md): free-only, CC0 preferred, justified verified CC-BY when useful, no paid dependency. Core buildings remain original/custom. Props must fit perspective/palette/materials, not be an arbitrary asset collage. Provenance precedes import.

Building V2, Environment V2, lights/shadows, richer loops, optional audio/haptics and contextual tutorial are planned #145–#150. Current title/processing effects do not imply those upgrades shipped. Future audio requires user gesture, mute/volume, bounded event cadence, cleanup and visual equivalents. No art-quality percentage is a measured acceptance target.

Azure badges remain independent and unchanged: no recolor/crop/distortion, building-texture baking or product-logo use. Do not copy competitor logos, screenshots, UI, characters or sounds. [Design References](GAME_DESIGN_REFERENCES.md) is text-only pattern commentary, not permission to reuse assets.
