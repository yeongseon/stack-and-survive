# 발표 대본 — 약 3분 / 8장

슬라이드: [slides.html](slides.html). 전체 원고 시간은 **약 180초의 목표 예산**이며 실제 발표 속도에 맞춰 리허설하세요. 이 자료 자체가 발표를 완료했다는 증거는 아닙니다. 별도 게임 한 판까지 3분에 들어간다고 주장하지 마세요.

## 1. 같은 트래픽, 다른 설계 — 0:00–0:20

“Stack & Survive는 클라우드 구조의 선택을 180초 생존 게임으로 만든 프로젝트입니다. 같은 트래픽에서도 서버를 언제 늘리고, 어디에 캐시와 보호 계층을 두느냐에 따라 결과가 달라집니다. 목표는 구조도를 보는 데서 끝나지 않고 선택의 결과를 직접 경험하게 하는 것입니다.”

## 2. 왜 게임인가 — 0:20–0:40

“서버를 늘리면 모든 문제가 해결될까요? App 처리량을 늘린 뒤 SQL이 새로운 병목이 될 수 있습니다. 플레이어는 수요와 압박을 읽고, 제한된 자금 안에서 선택한 뒤 가용성과 매출 손실로 결과를 확인합니다. 실제 학습 효과는 아직 참가자 검증이 필요한 가설입니다.”

## 3. 플레이 흐름 — 0:40–1:05

“다음 공격이 오기 전에 준비합니다. 비어 있는 시설을 한 번 클릭해 건설을 요청하지만, 건설 중에는 새 용량이 생기지 않습니다. 한 판은 180초, 여덟 단계이며 성공하면 더 높은 가용성 목표에 도전합니다. 화면의 달러는 시뮬레이션 사업 가치이고 실제 Azure 비용이 아닙니다.”

## 4. 전략의 차이 — 1:05–1:30

“App 확장에는 활성화 지연과 운영비가 있습니다. Cache는 적격 읽기 요청을 줄여 주지만 쓰기는 SQL로 갑니다. Edge는 봇을 걸러내지만 정상 고객을 오탐할 수 있습니다. 따라서 가장 높은 가용성과 가장 높은 종합 점수가 항상 같은 전략에서 나오지는 않습니다.”

## 5. 결과와 다시 도전 — 1:30–1:50

“점수와 결과는 즉시 나타납니다. 목표를 충족하면 이름을 입력해 순위에 참여할 수 있고, 기록된 이름과 앞으로 사용할 이름을 구분합니다. 여기 보이는 DEMO는 실제 자동 실행의 로컬 점수입니다. 전역 서버 검증이나 사람의 평가라고 주장하지 않습니다.”

## 6. 기술 구조 — 1:50–2:15

“React는 UI, Phaser는 월드를 담당하고, 별도의 결정론적 엔진이 규칙을 계산합니다. 선택적 Node API도 같은 TypeScript 엔진을 공유합니다. 클라이언트 점수를 믿는 대신 챌린지와 행동 기록을 받아 처음부터 재실행해 순위를 계산합니다. 닉네임 인증이나 모든 종류의 부정행위 방지를 제공하는 것은 아닙니다.”

## 7. 실패해도 이어지는 시연 — 2:15–2:40

“API가 없어도 게임과 로컬 결과는 동작합니다. 전역 검증과 로컬 기록을 명확히 구분하고, 일시정지·재시작·키보드·여러 화면 크기를 테스트합니다. 배포는 정확한 main 커밋의 CI와 실제 Pages 작업을 확인합니다. 사람의 이해, 실제 청취와 권리 검토는 자동 검사와 분리해서 기록합니다.”

## 8. 마무리 — 2:40–3:00

“같은 워크로드에서 다른 구조를 선택하면 생존도 달라집니다. 브라우저에서 계정 없이 시작할 수 있습니다. 다음 시도에서 무엇을 바꿀지 직접 확인해 주세요. README에는 실제 화면을 따라가는 사용법과 개발·기여 가이드를 함께 준비했습니다.”

## 시간이 추가로 있을 때만 라이브 시연

1. 깨끗한 브라우저로 [게임](https://yeongseon.github.io/stack-and-survive/)을 열고 선택적 이름 설정을 보여줍니다.
2. Start → 다음 웨이브 예고 → Cache/Edge 또는 App 요청 → 실제 건설 완료를 보여줍니다.
3. Pause → Learn → Resume로 설명 시간을 확보합니다. 멈춘 시간을 계속 흐르는 게임처럼 말하지 않습니다.
4. 완주 시간 예산이 없으면 결과는 **녹화된 다른 시점**이라고 말하고 이미지/영상으로 전환합니다.
5. 공개 리더보드에 시연용 점수를 반복 제출하지 않습니다. API가 실패하면 로컬 상태를 그대로 설명합니다.

## 예상 질문

자세한 답변은 [Judge Q&A](../docs/submission/JUDGE_QA.md)를 사용합니다.

- **실제 Azure가 생성되나요?** 아니요. 게임은 브라우저 시뮬레이션이고 선택적 순위 API가 별도로 Azure App Service에 배포됩니다.
- **실제 클라우드 가격/성능인가요?** 아니요. 게임을 위한 수치이며 운영 규모나 청구액 예측에 쓰면 안 됩니다.
- **점수는 믿을 수 있나요?** 로컬 기록은 수정할 수 있습니다. 전역 서버는 지원된 행동 기록을 재실행하지만 계정 인증·봇 방지까지 보장하지 않습니다.
- **AI를 썼나요?** 구현·원본 아트 반복·검사·문서 준비를 도왔습니다. AI 리뷰를 실제 참가자 또는 법적 승인으로 표시하지 않습니다.
- **다음 단계는요?** 실제 사람의 이해·자발적 재시도와 청취/기기 및 권리 조건 확인입니다. 새 기능을 이미 구현했거나 승인됐다고 약속하지 않습니다.
